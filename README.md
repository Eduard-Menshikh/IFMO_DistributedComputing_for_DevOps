# Kafka — брокер сообщений в распределённых системах

Apache Kafka — это распределённая commit log-платформа, обеспечивающая надёжную и масштабируемую доставку сообщений между компонентами систем. Она построена вокруг модели публикации-подписки и предназначена для высокопроизводительной обработки потоков данных.

Данные организованы в **топики**, которые делятся на **партиции**. Каждая партиция обслуживается одним брокером-лидером, остальные брокеры хранят реплики. Репликация обеспечивает устойчивость: при сбое лидера фолловер становится новым лидером.

Kafka использует модель "продюсер → брокер → консьюмер". Продюсеры публикуют сообщения в топики, часто с ключом, определяющим партицию. Консьюмеры читают данные, координируясь в **группах**: одна партиция — один консьюмер в группе.

Координация осуществляется через **KRaft (Kafka Raft Metadata Mode)** — встроенный механизм консенсуса, заменяющий ZooKeeper. Он реализует протокол **Raft** для управления метаданными (информация о топиках, брокерах, партициях). Один из брокеров играет роль **контроллера**, координируя выбор лидеров, создание топиков и регистрацию узлов. Все изменения записываются в журнал Raft и реплицируются между контроллерами.

Kafka достигает высокой производительности за счёт архитектурных оптимизаций. Данные записываются **последовательно на диск**, что снижает накладные расходы на I/O. Сообщения хранятся в **сегментированных логах**, что упрощает управление историей и удаление старых данных. Кроме того, Kafka активно использует **батчинг**: продюсеры и консьюмеры обмениваются данными пакетами, минимизируя издержки на обработку. Сообщения неизменяемы и упорядочены, что упрощает повторную обработку и восстановление состояния.

Kafka применяется в потоковой аналитике, CDC, логировании, микросервисной интеграции и мониторинге. Благодаря масштабируемости и отказоустойчивости, она стала стандартом для построения надёжных event-driven систем.
